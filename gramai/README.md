# GRAM AI — Whole Project

Final SIH-style prototype for strengthening farmer market linkages and price discovery.

## Included
- Secure login and registration
- Farmer / Buyer / Admin roles
- Optional SMTP delivery of temporary registration password
- Farmer profile + farm details + payout details + password reset
- Marketplace buy/sell
- Seller transport availability and delivery terms
- Buyer cost breakdown
- Orders and digital negotiation
- Verified buyers
- GPS-enabled transport network
- All-India mandi map
- Demand intelligence
- Revenue analytics
- Notifications
- Admin Mission Control
- Audit logs and rate limiting
- Multi-language interface: English, Hindi, Marathi, Tamil, Telugu
- Built-in GRAM AI chatbot
- 36 states/UT seeded coverage
- 72 market points
- 12 crops
- 30-day synthetic price/arrival history per crop/market
- XGBoost + LightGBM training
- 1-day, 3-day and 7-day price forecasts
- MAE, RMSE, MAPE and R²
- Adaptive model selection / ensemble
- Predictability Score
- Predictability graph
- Price forecast graph
- Explainable feature importance
- Multi-market comparison
- Transport + market charges
- Net Realizable Price
- SELL NOW / WAIT / SHIFT MARKET recommendation

## Important data note
The bundled dataset is synthetic/demo data generated by `seed.py` so that the whole prototype works immediately.
For a final production/SIH deployment, replace the seed data with official AGMARKNET/e-NAM data, weather data and verified logistics feeds.

## Setup on Windows
```powershell
cd gramai
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python seed.py
python warm_i18n.py
python -m uvicorn app:app --reload
```

Invoke tools as `python -m <tool>`. The `.exe` shims in `venv/Scripts`
hard-code the path the venv was created at, so they stop working if the
folder is moved; recreate the venv if you need them.

Open:
- Website: http://127.0.0.1:8000
- API docs: http://127.0.0.1:8000/docs

## Registration email
If SMTP is configured, GRAM AI sends a temporary password to the registered email.

Example for Gmail:
```powershell
$env:GRAMAI_SMTP_HOST="smtp.gmail.com"
$env:GRAMAI_SMTP_PORT="587"
$env:GRAMAI_SMTP_USER="your-email@gmail.com"
$env:GRAMAI_SMTP_PASSWORD="YOUR_GOOGLE_APP_PASSWORD"
$env:GRAMAI_SMTP_FROM="your-email@gmail.com"
python -m uvicorn app:app --reload
```

Use a Google App Password, not your normal Gmail password.

If SMTP is not configured, the local prototype still works and returns the generated temporary password in the registration response.

## Multilingual interface (all 24 languages)

The interface is translated at runtime, so nothing is hardcoded per language.

- `i18n_service.py` translates strings through a free, key-less provider
  (Google `clients5`, with MyMemory as a fallback) and caches every result in the
  `i18n_cache` table. A string is translated once and is instant forever after.
- `static/i18n.js` walks the rendered DOM after every route change and translates
  whatever it finds, including the text `app.js` builds inside template literals.
  Mark any element `data-no-i18n` to opt out.
- Kashmiri, Bodo and Rajasthani are not accepted by the provider, so they fall
  back to the closest supported language sharing the script (`ks`→Urdu,
  `brx`/`raj`→Hindi).

Pre-warm the cache so language switching is instant during a demo:

```powershell
python warm_i18n.py
```

This writes `static/i18n/<lang>.json` for every language (~11s each, once).

## GRAM Saathi assistant

`chatbot_api.py` exposes `/api/ai/*`. The model calls typed, read-only tools that
re-check the caller's role and user id, so it can answer from live platform data
(listings, orders, forecasts, mandi prices, rewards, payments, KYC, transport,
buyers, grievances, certificates) without ever seeing SQL.

Set the key in `.env` (never in `static/`, never committed):

```
GROQ_API_KEY=your-key-here
GROQ_MODEL=openai/gpt-oss-120b,qwen/qwen3.8-27b
```

Without a key the assistant falls back to the original keyword bot, so the
interface never shows a dead chatbot.

### Answer language

The assistant answers in the language the question was **written** in, detected
from its script - so a Tamil question gets a Tamil answer even while the
interface is in English. Latin-script questions follow the interface language.
The picker in the assistant header overrides this: `Auto` (the default) detects,
any other choice forces that language.

### Data shown with answers

Every answer that used platform data carries a collapsible **Data used** panel
rendering that data as labelled tables and rows - never raw JSON.

Voice uses the browser Web Speech API: speech-to-text with live interim text and
auto-send, speech-to-speech replies, and a hands-free mode that reopens the mic
after each answer. Voice input needs Chrome or Edge.

## Responsive layout

`static/responsive.css` carries the mobile and tablet rules. Below 900px the
sidebar becomes a labelled slide-in drawer (replacing the icon-only rail), and
below 780px the assistant becomes a full-width bottom sheet.
